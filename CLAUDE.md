## Layout
- `site/` – public marketing site, `rootsandpantry.co.uk`. Astro 7, static, **no JavaScript**, no cookies.
- `app/` – the real app, a Cloudflare Worker (plain JS, server-rendered HTML, no framework). `app.rootsandpantry.co.uk` (Worker `rp-app`, branch `main`, D1 `rp-app`) and `test-app.rootsandpantry.co.uk` (Worker `rp-app-test`, branch `test`, D1 `rp-app-test`, yellow TEST banner). D1 databases are EU jurisdiction. Config in `app/wrangler.jsonc`; schema in `app/migrations/`.
  - Built so far: contact form (`/contact`, saved to D1 + emailed to hello@ with reply-to), email-code sign-in (`/signin`, 6-digit code, HMAC-hashed, 10 min, 5 attempts, 3 codes/email/hour, 10/IP/hour, `__Host-rp_s` session cookie 30 days), producer sign-up (`/producer/join`, pending until approved; website and Facebook page both optional) and status page (`/producer`). OWNER_EMAIL (hello@) gets role `owner` on first sign-in.
  - Producer dashboard (step 3, `app/src/producer.js`): `/producer` (deals list with state live/waiting/scheduled/paused/expired/ended), `/producer/edit` (listing: shop address, market days, delivery reach), `/producer/deals/new` and `/producer/deals/:id/edit|status|renew` (rules enforced in `validateDeal`: ≥10% or free item, ≥14 days, max 366 days, online deals need a code, health-claim word check, max 10 live deals), `/producer/promote` (QR code + A4 poster + A6 postcard print pages – redesigned 15 Nov 2026 and approved by Jason: green band, deal headline + red stamp, QR + "how to claim" steps, deal chooser when several – + Facebook post text), public page `/p/:slug` (full page for approved producers, never shows codes or phone; visitors see a status message instead when pending ("is joining"), suspended ("paused for now", no reason shown) or withdrawn (410, "has left" – keep a tombstone row when listing deletion is built); rejected and unknown slugs get a 404 "isn't listed" with no name; the producer and admins see the full page with a preview note). Deals table in `migrations/0003_deals.sql`. Daily cron 08:00 UTC emails a reminder once when a deal ends within 7 days. Print sizes use separate `page-a4.css` / `page-a6.css` (Chrome ignores named @page and the `A6` keyword).
  - Offers & specials (18 Nov, `app/src/offers.js`, migration `0010_offers.sql`): second tier below the exclusive deals – the producer's own offers, open to everyone, no code. Kinds: multibuy | preorder | seasonal (gift boxes etc.); at least 3 days (`MIN_OFFER_DAYS`), max 366, max 10 live, price must contain a number, same health-claim check; for pre-orders `ends_on` is the order-by date (+ optional `ready_text`). Routes `/producer/offers/new` (`?christmas=1` presets a pre-order to 20 Dec) and `/producer/offers/:id/edit|status`; shown on the dashboard, the public page (below exclusive deals, soonest-ending first) and admin producer detail (end with reason, `/admin/offers/:id/end`, shares `postEndDeal`). Directory cards show offer counts and "Christmas orders".
  - Christmas page `/producers/christmas` (public): live Christmas-tagged offers and exclusive deals (`christmas` column on both) from approved producers, exclusive deals first then by order-by date; optional postcode district + miles filter (full postcode cut and redirected), includes producers that deliver there. Linked from the directory (Nov and Dec only, by date) and from site /how-it-works/ (static: **remove that link after Christmas**).
  - Facebook auto-posts (18 Nov, `app/src/facebook.js`, migration `0011_facebook.sql`, guide `docs/facebook.md`): a producer's first approval (not reinstatement) and each new offer from an approved producer are queued in `fb_posts` (unique per kind+item), held 1 hour (`HOLD_SECONDS`; future offers wait for their start date), then posted by the hourly cron to Graph API v27 `/{FB_PAGE_ID}/feed` (page API ID 1495690693621331; Meta app "Roots & Pantry posts"; token data access expires ~every 90 days, first ~16 Feb 2027 – repeat docs/facebook.md steps 4–7) with `link` = `/p/:slug` or `/p/:slug#offer-<id>`. Text is built at posting time; paused/ended/no-longer-live items are skipped. Never posted: exclusive deals, alcohol, codes, phone/email/full postcode. Needs `FB_AUTOPOST=on` + `FB_PAGE_ID` (vars) + secret `FB_PAGE_TOKEN` (live only); otherwise rows become `dry_run` with the text (test is always off). Admin → Facebook (`/admin/facebook`, owner + moderators): queue with draft text, Cancel / Post now / Try posting again. Failures email hello@ (token never in messages). Privacy notice "Who else handles it" mentions it.

## Working rules
- **Test first.** Work on `test`, Jason checks the preview URL, then merge to `main`. **Live since 15 Nov 2026:** pushing to `main` deploys the public site and the live app `rp-app` (Workers Builds, branch main, root /app, deploy = `npx wrangler d1 migrations apply DB --remote && npx wrangler deploy`; its own runtime secrets incl. a different CODE_PEPPER). Search indexing still off until Jason chooses launch day (`PUBLIC_INDEX=yes`).
- `cd site && npm run build && npm test` before every push. `npm test` runs axe-core (WCAG 2.2 AA) at desktop and phone widths, checks the CSP (no inline scripts or `style=` attributes), sideways scrolling and internal links. Needs Chrome (`CHROME_PATH`).
- **WCAG 2.2 AA is a hard requirement.** Yolk (#FFC93C) never for text on white. Visible focus, 44px tap targets, reduced-motion respected, captions on videos.
- **Strict CSP** in `site/public/_headers`: no inline styles/scripts, no third-party fonts or embeds (fonts are self-hosted via @fontsource). Only exception: Cloudflare Web Analytics beacon.
- **noindex until launch.** Pages emit `<meta name="robots" content="noindex">` unless the Cloudflare variable `PUBLIC_INDEX=yes` is set (production only, on launch day). `*.pages.dev` always sends `X-Robots-Tag: noindex`.
- Postal address and phone appear **only** on `/privacy-and-terms/`. Everywhere else: hello@ only.
- Plain UK English, short pages, specifics over adjectives. No secrets in the repo; never ask Jason to paste secrets in chat.
- Jason prefers direct, concise, step-by-step instructions for anything he clicks in Cloudflare or GitHub.
